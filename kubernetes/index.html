학습용 예제 비교입니다. 실제 kubectl이나 Kubernetes API를 실행하지 않습니다. 예시 출력은 설명용이며 실제 클러스터 상태와 다릅니다.

KUBERNETES PRACTICE LAB · 독립 실행판
LEARN · CONNECT · DEBUG

직접 치면 연결이 보입니다.

  1. YAML 따라치기: 리소스 선언을 입력하고 문제를 풉니다.
  2. 앱 연결 실습: ConfigMap·Secret → Deployment → Service를 연결합니다.
  3. 명령어 · 장애: 증상에 맞는 kubectl 명령을 쓰고 원인을 고릅니다.

YAML은 앞쪽 들여쓰기가 의미를 가집니다. 예제의 들여쓰기와 키 순서에 맞춰 연습합니다. 빈 줄·줄 끝 공백·전체 줄 주석은 비교에서 제외합니다. 의미가 같은 다른 YAML 표현도 이 연습에서는 다르게 판정할 수 있습니다.

Tab은 공백 두 칸, ⌘/Ctrl + Enter는 코드 확인입니다. 코드와 진도는 이 브라우저에 저장됩니다. 실제 Secret·kubeconfig·토큰을 입력하지 마세요.

웹 학습에는 클러스터가 필요 없습니다. 실제 적용은 별도의 로컬 실습 클러스터에서 진행하세요. 클라우드 클러스터·로드 밸런서·스토리지를 만들면 비용이 발생할 수 있습니다.

실제 앱을 실행해 보려면

이 웹에서는 클러스터를 만들지 않습니다. 로컬에 Docker 등 지원 런타임, kubectl, minikube를 설치한 뒤 전용 profile에서 진행하세요. 공식 설치 가이드 ↗

minikube start -p k8s-typing-lab
kubectl config current-context
kubectl get nodes
# 앱 연결 실습의 app.yaml을 저장한 뒤:
kubectl apply -f app.yaml
kubectl -n k8s-lab rollout status deployment/web
kubectl -n k8s-lab get pods,svc
kubectl -n k8s-lab port-forward service/web 8080:80

current-context가 의도한 로컬 클러스터인지 먼저 확인합니다. port-forward를 실행한 터미널을 유지하고 브라우저에서 http://127.0.0.1:8080을 엽니다. 이는 HTTP 앱 확인용이며 외부 Ingress 경로를 검증하지 않습니다.

기본 app.yaml은 Namespace·ConfigMap·가짜 Secret·Deployment·ClusterIP Service 5개입니다. PVC·HPA·Ingress는 포함하지 않습니다. 이미지 다운로드가 필요하며 환경에 따라 적용이 실패할 수 있습니다. 실제 클러스터 배포 성공은 이 웹 제작 과정에서 검증하지 않았습니다.

선택 확장

HPA는 Metrics API와 CPU requests가 필요합니다. minikube에서는 minikube addons enable metrics-server -p k8s-typing-lab로 지표 제공을 준비할 수 있습니다. Ingress는 별도의 관리 중인 컨트롤러·Class·호스트 경로가 필요합니다. lab-controller는 실제 환경에 맞게 바꾸는 예시 이름입니다.

Ingress NGINX 프로젝트는 2026년 3월 지원 종료 일정이 공지되었습니다. 이 실습은 그 컨트롤러의 신규 설치를 안내하지 않습니다. 신규 외부 경로는 환경에 맞는 지원 중인 구현과 Gateway API도 검토하세요. 공식 공지 ↗

정리

# context와 학습 데이터 보관 여부를 확인한 뒤 실행
kubectl delete -f app.yaml
# 별도로 만든 Ingress·HPA·PVC가 있으면 따로 확인
# PVC 삭제 전 PV reclaimPolicy와 데이터 보관을 검토
minikube delete -p k8s-typing-lab

app.yaml 삭제는 k8s-lab 네임스페이스도 삭제하므로 그 안의 다른 리소스에 영향을 줍니다. 전용 네임스페이스에서만 사용하세요. 실제 비밀 값과 kubeconfig는 저장소에 올리지 않습니다.
