      연결 확인 포인트
        이 연결의 공식 문서 ↗
        S3 연결 지도는 기존 프로젝트의 참조를 이해하기 위한 발췌입니다. 전체 Config 기록기·전달 채널·패키징·실행 권한 등은 별도 구성해야 하며, 이 예제들을 합치는 것만으로 전체 배포되지는 않습니다.
        

        웹 실습을 실제 AWS에서 해보려면
        웹 따라치기는 AWS에 연결하지 않습니다. 아래는 학습자가 별도의 실습 계정에서 직접 진행할 때의 순서입니다. 전체 코드는 연결 관계를 갖춘 예제이지만 실제 배포 성공을 검증하지 않았습니다.
        1. 별도의 빈 폴더를 만들고 전체 예제를 main.tf로 저장합니다. 기존 S3 프로젝트와 상태를 섞지 않습니다.
        2. AWS CLI 임시 자격 증명으로 로그인하고 계정·리전을 확인합니다. EC2·VPC·ELB·ASG 관리, SSM 공개 AMI 조회와 필요한 서비스 연결 역할 생성 권한도 확인합니다.
        3. client_cidr에는 접속할 본인의 공인 IPv4/32를 사용합니다. REPLACE_MY_IP는 실제 값으로 바꿔야 하며 0.0.0.0/0으로 넓히지 않습니다.
        4. init·validate·plan을 실행합니다. 생성·수정·삭제와 SG 범위를 검토한 뒤에만 apply합니다. 예제의 생성 리소스는 20개지만 실제 plan을 기준으로 확인합니다.
        5. ALB active와 target healthy까지 기다린 뒤 출력 URL을 허용한 IP에서 엽니다.
        

        mkdir terraform-connect-lab
cd terraform-connect-lab
# 다운로드한 main.tf를 이 폴더에 저장합니다.
# .gitignore에 .terraform/ · *.tfstate* · *.tfplan을 추가합니다.
aws sts get-caller-identity
terraform init
terraform fmt
terraform validate
terraform plan -var='client_cidr=REPLACE_MY_IP/32'
# plan을 검토한 뒤 직접 실행합니다.
terraform apply -var='client_cidr=REPLACE_MY_IP/32'
terraform output -raw web_url
        

        연결이 안 될 때
        • 시간 초과: 접속 IP/32, ALB SG, IGW·라우팅, ALB active 상태부터 확인합니다. 브라우저가 HTTPS로 강제 전환하면 이 HTTP 실습 주소와 구분합니다.
        • 503: listener의 대상 그룹, ASG의 target_group_arns, 실제 target 등록·healthy 상태를 확인합니다.
        • 502·비정상 대상: Web SG의 ALB 출처 80, Nginx 부팅·응답, health check 경로를 확인합니다. 부팅 로그는 cloud-init-output.log이며, 이 예제는 원격 접속용 IAM/SSM을 구성하지 않습니다.
        • 서버가 계속 교체됨: 초기 패키지 설치 경로와 health-check grace period를 확인합니다. 템플릿 변경은 기존 EC2를 자동 갱신하지 않으므로 instance refresh는 별도 설계합니다.
        

        # 출력 ARN으로 대상 상태를 확인합니다.
aws elbv2 describe-target-health \
  --target-group-arn REPLACE_TARGET_GROUP_ARN \
  --region ap-northeast-2
# 실습을 마치면 같은 폴더에서 삭제 계획부터 검토합니다.
terraform plan -destroy -var='client_cidr=REPLACE_MY_IP/32'
terraform destroy -var='client_cidr=REPLACE_MY_IP/32'
        

        EC2·EBS·ALB·public IPv4·전송 등에 비용이 발생할 수 있습니다. CPU 정책으로 서버가 최대 두 대까지 늘어날 수 있고, 기본 서버 한 대 구성은 고가용성이 아닙니다. 삭제 후 ASG·EC2·ALB·EBS·자동 생성 알람과 VPC의 잔여 항목을 확인합니다. NAT Gateway는 생성하지 않습니다.
        이 구성은 본인 IP로 제한한 HTTP 학습 환경입니다. 실제 서비스는 ACM HTTPS, WAF, 비공개 서버 배치와 필요한 외부 접속 경로, 로그·감사·백업 등을 추가로 설계합니다. 코드를 Git에 올릴 때 상태·plan·자격 증명은 제외하세요.
        EC2 요금 ↗ · 로드 밸런서 요금 ↗
        

        코드 확인은 학습용 토큰 비교이며 실제 Terraform validate·plan·apply를 실행하지 않습니다. 완료 표시는 따라쓰기 완료입니다. AWS에서 정상 연결됐다는 검증 결과와 구분하세요.
        

        HOW TO PRACTICE
        직접 치면 연결이 보입니다.
        1. 왼쪽 코드를 보며 오른쪽에 직접 입력하세요.
        2. 막히면 힌트를 열고 코드 확인을 누르세요.
        3. 설명용 plan을 읽고 이해도 문제를 풀어보세요.
        4. 둘 다 완료하면 다음 단계로 이동하세요.
        단계는 언제든 자유롭게 이동할 수 있습니다. 입력한 코드와 완료 기록은 이 브라우저에 저장됩니다. 들여쓰기·공백·일반 주석 차이는 코드 확인에서 무시합니다. 문자열 안의 값은 정확히 입력해야 합니다.
        상단의 AWS 서비스 사용법에서는 15개 서비스·구성 요소의 개념·설정 순서, Terraform 따라쓰기, 확인 명령과 오류 해결을 볼 수 있습니다.
        웹 학습에는 AWS 계정, 액세스 키, Terraform 설치가 필요 없습니다. 연결 실습에서 다운로드한 코드를 실제 AWS에 적용하면 비용이 발생할 수 있습니다.
